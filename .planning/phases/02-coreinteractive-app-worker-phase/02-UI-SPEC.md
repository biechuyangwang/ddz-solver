# Phase 2 -- UI Design Contract

> Visual and interaction contract for the Interactive App + Worker phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 CSS-first) |
| Preset | not applicable |
| Component library | none (custom React components) |
| Icon library | none (Unicode suit symbols for Phase 2; lucide-react deferred to Phase 3) |
| Font | System font stack (`font-sans` in Tailwind, renders as system default: Segoe UI / PingFang SC / Noto Sans SC) |

**Rationale:** Project uses Tailwind v4 with `@theme` directive for custom tokens. No component library (shadcn, Radix, etc.) is used. Phase 2's UI is simple enough that custom components suffice. Tailwind utilities handle all styling.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between card suit and value |
| sm | 8px | Compact element spacing, card inner padding |
| md | 16px | Default element spacing, card grid gaps, panel padding |
| lg | 24px | Section padding, panel vertical margins |
| xl | 32px | Layout gaps between major panels |
| 2xl | 48px | Major section breaks, top/bottom page margin |
| 3xl | 64px | Page-level spacing (not needed for Phase 2) |

Exceptions: none

**Tailwind mapping:** Use Tailwind spacing scale directly (`gap-1` through `gap-16`, `p-2` through `p-12`, etc.). All values are multiples of 4px in Tailwind's default scale, so no custom spacing tokens are needed.

## Typography

Declared weights: 2 -- 400 (regular), 600 (semibold).

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm leading-relaxed` |
| Label | 12px | 600 (semibold) | 1.33 | `text-xs font-semibold` |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |
| Display | 28px | 600 (semibold) | 1.2 | `text-3xl font-semibold` |

**Usage rules:**
- Body (400): All descriptive text, statistics values, card count labels, card suit symbols
- Semibold (600): Section headers ("我方手牌", "对方手牌"), button text, statistics field names, panel titles, result header ("求解结果"), app title ("斗地主残局求解器"), win/lose badge text ("必胜"), card face values, joker text

**Card face typography (component-scoped exception -- 16px is not part of the 4-size page scale; it is reserved for playing card face rendering only):**
- Card value: 16px, weight 600 -- `text-base font-semibold`
- Card suit symbol: 14px, weight 400 -- `text-sm`
- Joker text ("小王", "大王"): 12px, weight 600 -- `text-xs font-semibold`

Phase 2 requires these custom components. No registry or third-party component library.

| Component | Purpose | Key Interactions |
|-----------|---------|------------------|

- Card cell size: 48px x 64px (playing card aspect ratio ~2:3)

## Interaction States

### Card Selection Flow
1. User sees full deck grid, all cards available
2. User selects target player via toggle (default: "我方")
3. User clicks a card in the grid -- card count for that value increments for the active player
4. Card in grid shows subtle "selected" indicator (count badge or border change)
5. Card appears in the active player's HandDisplay
6. If max count (4 for regular, 1 for joker) reached across both hands, card becomes disabled in grid
7. User can click a card in HandDisplay to remove it, making it available again in the grid

### Solve Flow
1. User clicks "开始求解" button
2. Button transitions to "求解中..." with spinner and cancel button appears
3. Solver runs in Web Worker (UI remains responsive)
4. Elapsed time display updates ("已用时 Xs")
5. On completion: result panel appears with win/lose badge and stats
6. On cancellation: Worker terminated, status returns to idle
7. On timeout (10s): result shows "求解超时" error

### Validation Rules (inline, real-time)
- Running count per card value across both hands: max 4 (regular), max 1 (joker)
- Cards disabled in picker when combined count reaches max
- No explicit "submit validation" -- picker enforces constraints on selection
- Solve button disabled when either hand is empty

## Responsive Behavior (Desktop-first)

Phase 2 targets desktop browsers. Minimum viewport: 1024px wide. No mobile-responsive layout required for Phase 2 (deferred to v2 UX-01/UX-02 requirements).

At 1024px viewport:
- App content centered, max-width 800px
- Card picker grid: full 13-column layout
- Player panels: side-by-side if space allows, stacked vertically if not

## Accessibility Notes

- Card picker: each card button has `aria-label` with Chinese card name (e.g., "黑桃A", "红心K", "小王")
- Selected count shown via `aria-pressed` or similar on card buttons
- Solve button: `aria-busy` during solving, `aria-live="polite"` region for result
- Color is not the sole indicator: selected cards use both border color AND background tint
- Sufficient contrast ratios: all text meets WCAG AA (4.5:1 for body text, 3:1 for large text)
