    5. Create `src/solver/search.ts` implementing the core negamax search:

       Export `negamax` function with this signature:
       ```typescript
       function negamax(
         myHand: Hand,
         opponentHand: Hand,
         lastMove: Move | null,
         passCount: number,
         alpha: number,
         beta: number,
         deadline: number,
         tt: TranspositionTable,
         tree: TreeBuilder | null,
         isPlayerMove: boolean,
         nodeCounter: { count: number }
       ): number
       ```

       Implementation (per RESEARCH.md Pattern 3):
       a. Terminal states:
          - `handIsEmpty(myHand)` -> return 1 (current player won)
          - `handIsEmpty(opponentHand)` -> return -1 (opponent won)
       b. Time budget check (every 10000 nodes to reduce overhead):
          - Increment `nodeCounter.count`
          - If `nodeCounter.count % 10000 === 0` and `performance.now() > deadline`, return 0 (timed out / unknown)
       c. Transposition table lookup:
          - Compute hash via `tt.computeStateHash(myHand, opponentHand, lastMove, passCount)`
          - If `tt.get(hash) !== undefined`, increment `tt.hits`, return cached value
       d. Generate moves:
          - If `lastMove === null || passCount >= 2`: call `generateLeadingMoves(myHand)` -- free lead
          - Else: call `generateFollowingMoves(myHand, lastMove)` -- must beat lastMove
       e. Move ordering heuristic (for better alpha-beta pruning):
          - Sort moves: bombs first, then by mainRank descending. This causes early cutoffs.
       f. For each move:
          - Compute new state: `newMyHand = applyMove(myHand, move)`
          - If move is PASS: `newLastMove = lastMove`, `newPassCount = passCount + 1`
          - Else: `newLastMove = move`, `newPassCount = 0`
          - Create tree child node if tree is not null: `tree.pushChild(move, isPlayerMove)`
          - Recurse: `val = -negamax(opponentHand, newMyHand, newLastMove, newPassCount, -beta, -alpha, deadline, tt, tree, !isPlayerMove, nodeCounter)`
          - Pop tree node if tree is not null: `tree.popChild(val)`
          - Update best and alpha
          - If `alpha >= beta`: break (prune)
       g. Store in transposition table: `tt.set(hash, best)`
       h. Return best

       IMPORTANT edge cases from RESEARCH.md Pitfalls:
       - Pass transfer (Pitfall 2): When passCount >= 2, the current player leads freely. This is handled in step (d) by checking passCount >= 2.
       - PASS is always available in following mode (guaranteed by generateFollowingMoves from Plan 02).

    6. Run tests -- MUST pass.
